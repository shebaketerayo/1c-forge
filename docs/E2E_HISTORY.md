Модель `gemma4:26b-a4b-it-qat`, до 4 итераций самокоррекции, без визуальной проверки. Каждый прогон —
10 запросов из `samples/requests.json` в изолированных каталогах. Последний отчёт — [E2E_REPORT.md](E2E_REPORT.md).

«Платформа» — конфигурация загрузилась, модули чистые, БД обновлена, самотест прошёл.
«Успех» — ещё и соответствие запросу: состав объектов, ключевые понятия, направление движений.

Проваливаются разные запросы: модель недетерминирована, и надёжность каждого запроса меньше 100 %.
10/10 в прогоне 6 — один прогон после всех исправлений, а не гарантия: для оценки нужна серия.

Известная слабость, которую проверки пока не ловят (прогон 6, «Оборудование»): место установки сделано
измерением регистра сведений, а не ресурсом, и списание пишет «Количество 1» — отчёт «где сейчас
оборудование» покажет и списанное. Подсказку DSL «то, что меняется, — ресурс» модель проигнорировала.

## Что нашли провалы и что сделано

Каждый пункт закреплён тестом (unit и/или на платформе, со спецификацией модели из прогона как фикстурой).

| Находка | Где | Исправление |
|---|---|---|
| Кнопка «Сгенерировать» не запускала работу: Worker удалялся сборщиком мусора | UI | окно держит Worker до конца потока |
| Валидатор угадывал вид движения по словам: «Оплата» → Приход (долг растёт), «Продажа абонемента» → Расход занятий | аренда, спортзал | только однозначные слова и «пара» к известным движениям, остальное — вопрос модели с объяснением |
| Значение из карточки справочника не выразить в DSL | спортзал | источники `Реквизит.Поле`, `ТЧ.Колонка.Поле`, автоисправление имени справочника |
| Регистр остатков только растёт (оба документа — Приход) | аренда | ошибка, если документов несколько |
| Непериодический регистр сведений под регистратором: вторая запись с тем же ключом не проводится | оборудование | такой регистр делается периодическим |
| Самотест подставлял одно место в «Откуда» и «Куда» | оборудование | разные элементы для ссылок одного типа |
| Количество −1 в регистре сведений / «Приход −1» вместо расхода | оборудование, кафе, ремонт | ошибка с подсказкой про регистр остатков |
| Выручка по заказу — константа 1 | ремонт | денежный ресурс не заполняется константой |
| Расход с контролем остатков без единого прихода — не проведётся никогда | ремонт | ошибка «добавьте документ поступления» |
| Модель не догадывалась добавить в документ недостающий реквизит | оборудование | подсказка в ошибке, пустое измерение — ошибка |
| Свой запрос к `РегистрНакопления.X.Обороты` с голыми именами ресурсов | журнал оценок | суффиксы Оборот/Остаток дописываются автоматически |
| Статус-константа (перечисление) в движении не выражалась | оборудование | источник `Перечисления.Имя.Значение` |
| «Жёсткий» режим выбрасывал всё движение из-за одного поля | оборудование | выбрасывается только поле, если это не измерение |
| Последняя итерация тратила вызов модели, результат которого некому проверить | все | сразу отказ с перечнем ошибок |
| Незаполненный ресурс регистра сведений считался ошибкой (увольнение без должности — законно) | кадры | предупреждение вместо ошибки |
